​Let's take a look at the Splunk Web interface. ​After logging in to Splunk Enterprise, ​we are directed to an app. ​Apps are preconfigured environments ​that sit on top of your Splunk Enterprise instance, ​extending the pre-built knowledge and capabilities. ​You can think of them as workspaces ​built to solve a specific use case. ​The apps you see are defined by ​a user with a Splunk administrator role. ​A quick note on roles. ​Roles determine what a user is able to see, do, and interact with. 
​There are three main roles in Splunk Enterprise. ​The Administrator role, ​the Power role, ​and the User role. ​The administrator role is the most powerful, ​can install apps, ingest data, ​and create knowledge objects for all users. ​The power user can create and share knowledge objects ​with all users of an app and do realtime searches. ​The user role will only see their own knowledge objects ​and those that have been shared with them. ​Splunk Enterprise comes with two apps by default. ​The home app gives you a quick place ​to explore Splunk Enterprise. 
​It allows you to launch and manage other Splunk apps, ​find documentation, ​and set a custom dashboard as your default dashboard. ​Administrators can also add apps and data from here. ​The other default app is the Search &amp; Reporting app. ​Hundreds of apps are available on Splunkbase, ​or you can build your own. ​I have added a link to Splunkbase to your notes. ​The Search &amp; Reporting app provides a default interface ​for searching and analyzing data. ​There are eight main components ​to the Search &amp; Reporting app's interface. 
​The Splunk bar appears on every page in Splunk Enterprise. ​You can use it to switch between apps, ​edit your account, view system-level messages, ​manage and edit your Splunk configuration, ​monitor the progress of search jobs, ​and find help. ​The app bar allows you to navigate the application. ​The search bar is used to run searches. ​You type in your search string and hit enter, ​or click the search icon to start a search. ​The time range picker is used to retrieve events ​over a specific time period. ​There is a "How to Search" panel ​with links to documentation and a search tutorial. 
​By clicking on the "Data Summary" button, ​you get a breakdown of the data ​indexed by host, source, and sourcetype. ​We talked earlier about sourcetypes being a classification of your data. ​The source is the file or directory path, ​network port, or script from which the event originated. ​And the host is the host name, IP address, ​or fully qualified domain name of the machine ​from which the event originated. ​Table Views provides a UI-driven way ​to explore and prepare your data ​without using Splunk's Search Processing Language. ​The Search History menu allows you to view and re-run past searches. ​We can narrow our search history ​by entering search terms into the filter window, ​and filter to show searches executed today, ​over the last seven days, ​or over the last thirty days.
