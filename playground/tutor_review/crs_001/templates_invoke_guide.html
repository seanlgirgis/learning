Templates & invoke

Sean’s unified model: three template classes, one fill step, one real pipeline call. Companion to the runnable files in this folder.

Story in one line: BUILD a recipe → FILL blanks with a dict → RUN the chain to get the LLM answer.
Stage 1

BUILD

Create the template object. No network. No tokens.

Stage 2

FILL

template.invoke({...}) substitutes blanks. Still no LLM.

Stage 3

RUN

chain.invoke({...}) fills + calls the model. This can charge.

Three classes → three builders

Each class is a recipe. The builder method (or constructor) matches the shape of that recipe.

Class Shape How you BUILD
PromptTemplate One string with blanks · no turns from_template("...{blank}...")
ChatPromptTemplate Ordered turns + blanks · roles from_messages([(role, content), ...])
FewShotPromptTemplate Prefix + example rows + suffix · 2+ shots Constructor: examples, example_prompt, prefix/suffix
Trap: from_messages is the builder. invoke is the fill (or fill+run on a chain) — not how you create the chat template.

A chat is an ordered list of turns. Each turn = role + content.

Invoke: prepare vs answer

CallWhat you getLLM / cost?
template.invoke({...}) Prepared prompt — string via .to_string() or chat via .messages No model charge
model.invoke(...) Model output (you already prepared input) Yes — charges
chain.invoke({...}) Full pipe: fill → model → parser Yes — charges 
chain = prompt | model | StrOutputParser()
answer = chain.invoke({"topic": "RAG"})   # real path day-to-day

ChatOpenAI(...) only builds the client. Free until an invoke that hits the model.

Not LangChain? You can still call the OpenAI SDK directly (client.chat.completions.create). LangChain is optional glue for templates, pipes, RAG. model.invoke is still LangChain — just the model runnable without a full chain.

Recall anchors (say these out loud)

from_template  → blanks in ONE string (no turns)
from_messages  → blanks + turns
invoke(dict)   → FILL blanks
chain.invoke   → FILL + LLM answer
